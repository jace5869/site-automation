FIX (one change for all 235)
Set these two settings, then run "AAP - set up job templates" and "AAP - set up portal actions"
(and the workflow gates job) with aap_templates_describe_overwrite as needed:
  aap_templates_description_owner: "SITEA operations team"
  aap_templates_description_contact: "SITEA automation team, automation@corp.example.mil"
Where: playbooks/group_vars/all.yml (one place, all three jobs read it), or the Variables of each
job: aap/extra_vars/aap_templates_setup.yml, aap_portal_setup.yml, aap_workflow_gates.yml
(commented lines 87-90, 130-133, 61-64).
Suggested line each template gets:
  ** Contact: Owner=SITEA operations team, Developer=SITEA automation team, automation@corp.example.mil
Use the same wording on all, or one owner per area (Linux, Windows, VMware, Network, Portal)
if different teams own them.

WATCH OUT
- 22 entries have made_by: AAP - set up portal actions. The PORTAL job writes their
  description, so it needs the same two settings, or those 22 stay without Contact.
- Descriptions already written by hand are not changed unless aap_templates_describe_overwrite: true.
- Contact is the only part that is not in git. If the settings are lost, the next run writes
  descriptions with no Contact line. Keep the settings in group_vars so they survive.
